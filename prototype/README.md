# 일자리 탐색 · 1차 제출용 작동 시안

`index.html`을 Edge 또는 Chrome으로 열면 바로 동작합니다. 설치나 빌드, 로그인은 필요하지 않습니다. 배포할 때에는 이 폴더의 HTML, CSS, JavaScript 및 assets를 함께 올려 주세요.

## 체험 순서

1. 흰색 손잡이를 아래로 당기면 아래쪽이 위로 넘어가며 카드 뒷면에 **플러팅을 날렸습니다**가 나옵니다. 약 2초 뒤 다음 화면으로 이동하며, **다음 공고 보기**를 눌러 바로 이동할 수도 있습니다.
2. 손잡이를 위로 밀면 위쪽이 아래로 넘어가며 거절 사유 뒷면이 나옵니다.
3. 뒷면에서 **급여 / 거리 / 업무 / 정보부족 / 기타**를 클릭하여 선택합니다. 복수 선택할 수 있습니다.
4. 사유가 없으면 완료할 수 없습니다. 기타 선택 시 구체적 사유도 입력해야 합니다.
5. **선택 완료 · 다음 공고**를 누르면 거절 기록을 남기고 다음 공고를 보여줍니다. **다시 볼게요**는 같은 공고 앞면으로 돌아갑니다.
6. 공고 6개를 모두 처리하면 요약과 **다시 체험하기**가 나옵니다.

카드 앞면이나 손잡이를 드래그할 수 있습니다. 손잡이의 위/아래 버튼은 클릭 대체 동작입니다. 키보드는 Tab/Enter, 손잡이에 포커스한 상태에서는 ↑/↓ 키를 사용할 수 있습니다.

**공고 상세보기**를 누르면 같은 카드 아래로 업무 소개·근무 조건·회사 정보가 펼쳐집니다. 페이지를 내려 읽으면 하단에 핸들이 나옵니다. 상세 내용을 펼친 동안에는 카드 본문의 터치가 스크롤로 동작하고, 지원·거절은 하단 핸들로 조작합니다. 위쪽 **상세 닫기** 버튼으로 접을 수 있으며, 상세 내용 맨 아래에는 별도 닫기 버튼이 없습니다. 새 공고는 항상 접힌 상태로 시작합니다.

상세보기 버튼은 해시태그 아래에 전체 너비로 배치됩니다. 열기와 닫기 모두 0.26초 동안 부드럽게 전환되고, 모션 감소 설정에서는 즉시 전환됩니다.

헤더는 아래로 스크롤하면 숨고, 위로 살짝 스크롤하면 화면 상단에 다시 나타납니다.

헤더 오른쪽 햄버거 버튼을 누르면 오른쪽에서 앱 화면 너비의 약 2/3인 사이드바 메뉴가 나옵니다. 왼쪽 검은 배경, 닫기 버튼, Esc 키로 닫습니다. 하단 고정 메뉴는 없으며, 도움말 물음표는 남은 공고 수 오른쪽에 있습니다.

새 공고가 나타나고 3초간 조작하지 않으면 손잡이가 아래로 8px씩 두 번 움직입니다. 공고당 한 번만 실행되며 지원 처리는 하지 않습니다. 사용자가 조작하거나 도움말을 열면 취소되고, 기기의 모션 감소 설정을 켜면 실행되지 않습니다.

헤더 중앙은 **로고와 잡아24**, 오른쪽은 햄버거 메뉴입니다. 남은 공고 수와 ? 도움말은 그 아래 안내 문구 오른쪽에 있습니다. 지원·거절 확정 시에만 공고 수가 줄어듭니다. 사이드바의 **나의 매칭**은 독립 페이지로 이동하고, **피드백**은 이번 체험에서 남긴 거절 기록을 보여 줍니다.

## 파일 구성

- `index.html`: 화면 구조 및 접근성
- `css/styles.css`: 색상, 크기, 반응형 배치, 카드 뒤집기 애니메이션
- `js/app.js`: 화면 갱신, 드래그/클릭, 피드백 선택
- `js/state.js`: 지원/거절/취소 상태 및 필수 사유 검증
- `js/jobs.js`: 가상 공고 6개
- `assets/office.jpg`: 사용자 제공 PDF에서 추출한 사무실 사진

색상과 손잡이 높이는 `css/styles.css`의 `:root` 변수에서 바꿀 수 있습니다. 카드 높이는 현재 보이는 면의 내용과 안쪽 여백에 따라 자동으로 정해집니다. 공고 내용은 `js/jobs.js`에서 수정합니다. HTML/CSS는 스페이스 4칸으로 들여쓰기합니다.

## 시안 범위

실제 기업 지원, 고용24 API, 로그인, 서버 저장, 기업 매칭은 연결되어 있지 않습니다. 체험 기록은 현재 탭의 sessionStorage에 보관해 페이지 이동과 새로고침 시 유지합니다. 탐색 완료 후 다시 체험하기로 초기화할 수 있습니다. 저장이 차단된 환경에서는 메모리에서만 동작합니다. 실제 공고나 실제 지원 완료로 제출하지 않도록 시연용임을 화면에 표시했습니다.

## 검증 실행

Node.js가 설치된 환경에서:

```powershell
node --test tests/state.test.cjs
node tests/browser.cjs
node tests/flip.cjs
node tests/card-layout.cjs
node tests/handle-hint.cjs
node tests/inline-details.cjs
node tests/details-collapse.cjs
node tests/sidebar.cjs
node tests/menu-motion.cjs
```

브라우저 테스트는 Playwright와 Edge가 필요합니다. 이 작업 환경의 번들 Playwright 경로가 기본값이며, 다른 환경에서는 `PLAYWRIGHT_PATH`에 Playwright 패키지의 절대 경로를 지정하세요.

실제 iOS Safari 기기 검증은 수행하지 않았습니다.

## 나의 매칭

`html/matching.html`과 `js/matching.js`는 제공된 SVG를 바탕으로 만든 독립 매칭 페이지입니다. 기존 헤더·사이드바·통합 CSS를 사용합니다.

- 기본 예시 공고 8건을 표시합니다. 탐색 페이지의 지원·거절 기록은 매칭 목록에 연동하지 않습니다.
- 전체 / 진행 중 / 매칭 성사 / 종료 / 넘긴 공고 필터와 최근 업데이트순 / 마감 임박순 정렬을 제공합니다.
- 상단 알림을 누르면 확인할 요청 2건만 표시하고, 다시 누르면 전체를 표시합니다.
- 요청·면접·공고 확인 버튼은 예시 내용을 보여 줍니다. 실제 서류 제출·면접 일정 조율은 연결하지 않았습니다.
- 추가 검증: `node tests/matching.cjs` (로컬 미리보기 서버 4173 포트 필요).

## 피드백

`html/feedback.html`은 기존 공통 CSS와 `css/feedback.css`를 사용하는 주간 지원 리포트 목록 시안입니다. 탐색·매칭 메뉴의 피드백에서 이동할 수 있습니다.

- 쿠폰 2장, 다음 쿠폰까지 7/10회, 주간 리포트 3개를 표시합니다.
- 상태 비교를 위해 마지막 리포트는 열람 완료로 시작합니다.
- 쿠폰 사용 버튼은 잔여 수량을 차감하고 열람 완료/다시 보기로 전환합니다. 다시 보기는 추가 차감하지 않습니다.
- 물음표 버튼에서 쿠폰 안내를 확인할 수 있습니다.
- 보고서 상세 화면은 후속 작업입니다. 현재 버튼은 상태 전환과 안내만 제공합니다.
- 쿠폰과 열람 상태는 이 화면에서 시연하는 메모리 상태이며, 새로고침하거나 재진입하면 초기 예시로 돌아갑니다.

## 폴더 구조와 미리보기

- `index.html`: 메인 탐색 페이지 및 진입점
- `html/`: 매칭, 피드백 목록, 피드백 보고서 페이지
- `css/`: 공통 및 페이지별 스타일시트
- `js/`: 화면 동작, 공고 데이터, 세션 상태 코드
- `assets/`: 로고, 사진, SVG 등 정적 이미지
- `tests/`: 상태 로직과 브라우저 동작을 확인하는 개발용 자동 검증 코드. 실제 화면에서 불러오지 않습니다.

`prototype` 폴더를 서버 루트로 사용하고 `http://127.0.0.1:4173/index.html`을 엽니다. 다른 페이지도 `/html/` 아래에 있습니다. 배포 시에는 최상위 `index.html`과 `html`, `css`, `js`, `assets` 폴더의 상대 위치를 유지하세요.

`index-unified.html`은 기존 `index.html`과 문서 제목만 다른 미사용 중복본이어서 제거했습니다.
